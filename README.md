# QuadClaude

Launch **four Claude Code terminals** in a 2×2 grid on your biggest monitor, each
with a glowing border and sound cues that tell you — at a glance across the room —
which windows are done, which need your input, and which are still thinking.

Each quad runs in its own **git worktree**, so you can drive four independent
tasks in parallel without them stepping on each other. An optional Monday.com panel
can show your task board alongside the terminals.

QuadClaude is a Windows C#/WPF app. A macOS (Swift/AppKit) port lives in
[`QuadClaudeMac/`](QuadClaudeMac/) — see [macOS](#macos).

---

## What it does

- **`launch`** — opens 4 terminals and snaps them into a 2×2 grid on your largest
  monitor. Each terminal runs the launch script, which sources the onboarding
  checklist and then starts `claude`.
- **`glow --color green|red`** — draws a pulsing neon border around the terminal
  window. Green = Claude finished. Red = Claude needs a permission decision.
- **`kill-glow`** — removes the border.

Supported terminals: **Windows Terminal** and **Warp**. QuadClaude finds the right
window by walking up the process tree, so it never glows an unrelated app.

---

## Prerequisites

- **.NET 9 SDK** — required to build (QuadClaude targets `net9.0`; an older SDK
  like .NET 8 can't build it). `install.bat` / `setup.sh` will **auto-install it
  with winget** if it's missing, or grab it from
  <https://dotnet.microsoft.com/download/dotnet/9.0>.
- **Git for Windows** — provides the `bash` used by the launcher
- **Claude Code CLI** — installed and working

## Quick start

```bash
# 1. Clone
git clone https://github.com/jamesonhussey/quad-claude-standalone.git
cd quad-claude-standalone

# 2. Install (builds with dotnet publish, creates shortcuts)
install.bat

# 3. Configure (writes the shared config file)
QuadClaude\publish\QuadClaude.exe setup
```

`install.bat` is the primary path for a new user: it builds QuadClaude, creates
Start Menu / taskbar shortcuts, and runs `QuadClaude.exe setup` for you. Prefer
bash? `bash setup.sh` does the equivalent as a fallback.

Then launch QuadClaude (from the shortcut, or `QuadClaude.exe launch`) and you'll
get your four terminals.

## Mental model: shared config, per-quad worktrees

There are only two kinds of state to think about:

- **One shared config file** at `%APPDATA%\QuadClaude\config.json`, generated by
  `QuadClaude.exe setup`. Whatever you set here applies to **all four quads** —
  permission mode, sounds, base branch, Monday settings, everything. Re-run
  `setup` any time to change it.
- **Each quad's git worktree** — the one genuinely per-quad thing. Every quad has
  its own physical worktree folder so four Claudes can work independent branches
  at once.

You do **not** configure quads individually. Set it once, it applies everywhere;
the only per-quad step is creating that quad's worktree.

### Onboarding appears automatically

Each time a quad opens, the launch script sources `onboarding.sh`. Until a quad is
fully set up it shows a **per-quad checklist** plus a short **git-worktree /
base-branch tutorial**, so a first-time user never has to know worktree commands
up front. The menu:

| Key | Action |
|-----|--------|
| `s` | Run the shared setup (`QuadClaude.exe setup`) |
| `w` | Make **this** quad's worktree |
| `a` | Make **all four** worktrees |
| `t` | Show the git-worktree / base-branch tutorial |
| `r` | Re-check setup status |
| `Enter` | Skip for now |

Once everything's set up, the checklist stops appearing and the quad goes straight
to `claude`.

### How worktrees work (high level)

A **git worktree** is a second working folder attached to the same repository, with
its own checked-out branch. QuadClaude gives each quad one, all cut from your
**base branch** (`worktreeBaseBranch`, default `main`). When a quad opens, the
launcher **resets that worktree to the base branch** so every task starts clean —
you branch off, do your work, push, and return to the base branch. The in-terminal
tutorial (`t` in the menu) walks through the details.

## How the hooks work

`setup` wires QuadClaude into Claude Code's lifecycle via `~/.claude/settings.json`:

| Event | What happens |
|-------|--------------|
| **Stop** (Claude finishes) | Green glow border + inbox sound |
| **UserPromptSubmit** (you send a message) | Kill the glow border |
| **Notification — `permission_prompt`** | Red glow border + alert sound |
| **Notification — `idle_prompt`** | Alert sound |

Sounds live in [`notification-pack/`](notification-pack/).

## Helper commands

QuadClaude bundles a few optional Claude Code slash-commands (in
[`.claude/commands/`](.claude/commands/)):

| Command | What it does |
|---------|--------------|
| `/explain-quad-claude` | Explains QuadClaude — the glow/sound cues, worktrees, the push→base-branch flow, and how to turn off anything you don't like |
| `/review-pr` | Reviews the current branch's diff vs the base branch like a thorough PR reviewer |
| `/commit-and-pr` | Commits your work, pushes the branch, and opens a PR into the base branch |
| `/sync-base` | Refreshes the current worktree with the latest base branch (without discarding work) |
| `/new-worktree` | Guided creation of an extra git worktree from the base branch |
| `/clean-worktree` | Safely removes a worktree (and optionally its branch) — the inverse of `/new-worktree` |
| `/quad-doctor` | Diagnoses your setup (config, launch env, worktrees, hooks) and suggests fixes |

During `QuadClaude.exe setup` you're **asked** whether to install these into
`~/.claude/commands/`, which makes them available in **every** Claude Code session
on your machine — including your work worktrees (which are separate repos). It's
opt-in and copy-if-missing (it never overwrites a command you already have). To
remove any later, just delete its `.md` file from `~/.claude/commands/`. Run
`/explain-quad-claude` first — it's the guided tour.

## Optional: Monday.com panel

Monday is **fully optional and off by default** — the master switch `mondayEnabled`
is `false`, every Monday field defaults to empty/0, and there's **no Monday button
or panel in the overlay** until you turn it on. To enable it, run
`QuadClaude.exe setup`, set `mondayEnabled` to `true` in the config, and fill in
your Monday values (`mondayApiToken`, `mondayBoardId`, `mondayHost`,
`mondayGroupId`, `mondayUserId`). The panel then shows that board group's tasks
beside your terminals. (The code stays in the build either way — the switch just
hides the UI.)

The CLI fetch backend is `monday-tasks.mjs`; you can test it directly:

```bash
MONDAY_API_TOKEN=xxx node monday-tasks.mjs \
  --board <id> --group <group> --host yourco.monday.com
```

---

## Config reference

All fields live in the one shared `%APPDATA%\QuadClaude\config.json`, written by
`setup`. The notable ones:

| Field | Default | Meaning |
|-------|---------|---------|
| `worktreeBaseBranch` | `"main"` | Branch each worktree is cut from and reset to when a quad opens |
| `worktreeProvisionCommand` | `""` | Optional shell command run **once** in a fresh worktree (e.g. `npx prisma generate`) |
| `devServerSubdir` | `""` | Optional monorepo subdirectory to run in |
| `mondayEnabled` | `false` | Master switch for the Monday panel + button (off = no Monday UI at all) |
| `mondayApiToken` | `""` | Monday API token (blank = Monday off) |
| `mondayBoardId` | `0` | Monday board id |
| `mondayHost` | `""` | Your Monday host, e.g. `yourco.monday.com` |
| `mondayGroupId` | `""` | Board group id |
| `mondayUserId` | `0` | Your Monday user id |

Everything except each quad's physical worktree folder is shared across all four
quads.

## Building from source

```bash
cd QuadClaude
dotnet publish -c Release -r win-x64 --no-self-contained -o publish
```

The output is `QuadClaude/publish/QuadClaude.exe`. QuadClaude targets
**.NET 9 / Windows (WPF)** and must be built on Windows. If you switch terminals,
add the new process name to the terminal-detection list in the source.
